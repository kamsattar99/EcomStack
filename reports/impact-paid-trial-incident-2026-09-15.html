The store owner reports completing Shopify’s paid trial after using their EcomStack account’s tracked affiliate link. 4. Cause assessment

Confirmed application-side blockers

  • Automatic sync is intentionally disabled. Required verification and approval flags are false. The worker will not process grants in this state.
  • No successful automated sync is evidenced. The workspace database contains no sync checkpoint. A scheduled production worker has not been established by this investigation.
  • The original Verify implementation was incomplete. It refreshed a timestamp instead of querying Impact. That defect has been corrected, but the correction does not create missing attribution data.

Unresolved attribution questions — not established causes

  • Has Shopify’s paid-trial event for this exact store reached Impact yet?
  • Does this Shopify campaign preserve and return partner-supplied subId1 on Paid Trial actions?
  • Did the claim survive the actual user’s entire alias/redirect/signup journey? A successful redirect-chain test alone does not prove parameter persistence or conversion attribution.
  • Was the conversion attributed to a different referral source, excluded by eligibility rules, or reported through another field/report?
  • Does the API response expose the required field in a different shape or endpoint? The checks inspected the adapter’s four top-level supported attribution fields, not every possible report.

5. Current Verify button behavior

The signed-in member’s button now checks the Impact reporting window for their server-stored claim, with a one-minute check limit. It distinguishes no observed match, a related but nonqualifying event, and a qualifying paid-trial match. When automatic verification is disabled, this is a read-only evidence check; it does not grant access even if a match appears.

Type checks and fixture tests passed for absent, free-trial, qualifying, reversed and unrelated-account events, plus a provider authentication error. These checks do not replace a successful live paid-trial attribution test.

6. Required investigation and resolution

  1. Locate the store’s actual conversion. Ask Shopify/Impact to trace jgz0ax-ua.myshopify.com and confirm whether a Paid Trial action exists, its attribution destination, state and reporting time. Provide the exact payment time privately if requested.
  2. Confirm the supported tracking contract. Establish whether subId1 → SubId1 is supported on campaign 13624, event 34051. Obtain the authoritative reporting endpoint/field if another mapping is required.
  3. Compare the exact claim securely. Verify the returned value against the local claim without placing it or credentials in public logs or support documents.
  4. Confirm the incentive is permitted. Validate the affiliate program’s approval for unlocking a resource library as a referral incentive. Do not treat technical attribution as commercial approval.
  5. Enable verification only after proof and approval. Then run the transactional sync and confirm exactly one entitlement is issued to the correct member.
  6. Configure durable recurring execution. Schedule the worker against the intended environment’s database and secrets, and demonstrate successful checkpoints, failure visibility and safe duplicate processing.

Do not repeat the purchase to diagnose this incident. Keep the existing store, claim and payment evidence. Do not manually label the account “verified” solely on the owner’s payment statement.
